# 예정된 운동 미리보기 + 세션 수정 설계

## 배경

기록 탭("예정된 운동" 섹션)의 항목을 탭하면 `app/(tabs)/templates.tsx`가 곧바로
`router.push({ pathname: /workout/${Date.now()}, params: { templateId } })`를 호출해서
확인 없이 라이브 워크아웃 세션이 시작된다. `workoutSessionStore.startSession()`이
그 시점에 호출되어 앱 전역 "운동 중" 배너까지 켜진다.

사용자 요청으로 범위가 확장되어, 단순히 이 즉시-시작 버그를 고치는 것을 넘어
예정된 운동에 대해 **그날 한정으로 세트/횟수/무게를 수정**할 수 있는 기능을
함께 설계한다. 수정은 원본 루틴 템플릿에는 영향을 주지 않는 독립 사본이어야 한다.

bali-backend 세션(`bali-backend-00`)과 협의한 결과:

- `WorkoutSession`이 이미 "템플릿에서 스냅샷 복제된 독립 occurrence" 모델이다.
  `POST /api/v1/sessions`가 `templateId`+`date`를 받아 `TemplateItem`을 값만
  복사한 `SessionLog`로 만든다 (FK 연결 없음 — 수정해도 템플릿 불변).
- 세션 상태를 명시적으로 표현하기 위해 백엔드에 `SessionStatus` enum
  (`SCHEDULED`/`IN_PROGRESS`/`COMPLETED`)과 `sessions.status` 컬럼을 추가하기로
  합의했다 (별도로 `bali-backend-00`이 진행). 세션은 항상 `SCHEDULED`로 생성되고,
  이후 상태 전이는 프론트가 기존 `PATCH /api/v1/sessions/{id}`에 `status` 필드를
  실어 명시적으로 트리거한다.

프론트엔드는 아직 전부 mock 데이터이므로 이번 작업에서 실제 API 연동은 하지 않지만,
데이터 모델은 위 백엔드 컨벤션(`SessionStatus`, 독립 사본)에 맞춰 둔다.

## 범위

**포함:**
- `UpcomingWorkout`에 `status`(`SessionStatus`)와 독립 아이템 사본(`items`) 추가
- 새 미리보기 화면 `app/upcoming/[id].tsx` (기존 `routines/[id].tsx`와 같은 패턴,
  단 이건 독립 사본을 보여주고 수정 가능하다는 점이 다름)
- `templates.tsx`의 예정된 운동 항목 tap 목적지를 미리보기 화면으로 변경
- "시작하기" 시 세션 id를 새로 만들지 않고 upcoming workout의 기존 id를 재사용
- 세트/횟수/무게 수치만 수정 가능 (운동 추가/삭제/순서 변경 제외)

**제외 (다음으로 미룸):**
- `UpcomingWorkout`과 `SessionRecord`(지난 기록) 완전 통합 — 화면마다 보여주는
  필드가 상당히 달라(지난 기록은 운동명 요약, 예정된 운동은 name/level/duration/
  썸네일) 지금 합치면 blast radius가 커진다. mock→실제 API 연동 작업 때 자연스럽게
  다루는 게 맞다.
- 실제 백엔드 API 호출 (계속 mock 유지, 백엔드 `SessionStatus` 작업 완료 후 별도 작업)
- 운동 목록 자체 편집(추가/삭제/순서) — `routines/new.tsx`의 exercise-picker 재사용은
  다음 단계
- 기록 탭에서 "예정된 운동" 카드에 상태 뱃지를 보여줄지 여부 — 이번 스펙에서는 다루지
  않음, 필요해지면 별도로 결정

## 데이터 모델

`constants/sessionRecords.ts`에 추가/변경:

```ts
export type SessionStatus = "SCHEDULED" | "IN_PROGRESS" | "COMPLETED";

export type UpcomingWorkout = {
  id: string;
  date: string;
  name: string;
  level: string;
  duration: string;
  muscleGroup: MuscleGroup;
  templateId: string;       // 파생 출처 참조용. 런타임에 운동목록 소스로 쓰지 않음
  status: SessionStatus;    // 시드 데이터는 전부 "SCHEDULED"
  items: TemplateItem[];    // 독립 사본. 여기서 수정해도 템플릿(templatesStore)엔 무영향
};
```

`TemplateItem`은 `store/templatesStore.ts`에 이미 정의되어 있으므로 import해서 재사용한다
(exerciseId, sortOrder, targetSets/targetReps/targetWeight 등 backend `TemplateItem`과
동일한 필드 이름을 프론트에서도 그대로 씀 — 나중에 실제 API로 바꿀 때 필드 매핑이 필요 없게).

시드 데이터의 `items`는 원래 참조하던 템플릿의 `items`를 그대로 복사해서 채운다
(런타임 클론 로직 없이, 애초에 독립된 값으로 하드코딩 — mock이므로 충분).

`SESSION_RECORDS`(지난 기록)의 기존 `status: "완료" | "진행중"` 타입은 이번엔 건드리지
않는다 (범위 제외 항목 참고).

## 스토어

새 파일 `store/upcomingWorkoutsStore.ts`. `store/templatesStore.ts`와 동일한 패턴
(zustand, in-memory, AsyncStorage 없음, mock 데이터를 초기 state로):

```ts
type UpcomingWorkoutsState = {
  workouts: UpcomingWorkout[];
  getUpcomingWorkout: (id: string) => UpcomingWorkout | undefined;
  updateItem: (
    workoutId: string,
    itemId: string,
    updates: Partial<Pick<TemplateItem, "targetSets" | "targetReps" | "targetWeight">>
  ) => void;
  markStarted: (workoutId: string) => void; // status를 "IN_PROGRESS"로 변경
};
```

## 화면 / 컴포넌트

### `app/(tabs)/templates.tsx`

예정된 운동 `Pressable`의 `onPress`를 다음으로 교체:

```ts
onPress={() => router.push(`/upcoming/${workout.id}`)}
```

`router.push({ pathname: /workout/${Date.now()}, ... })` 호출은 제거.

### 새 화면 `app/upcoming/[id].tsx`

`app/routines/[id].tsx`("루틴 상세")와 레이아웃을 맞추되(헤더+뒤로가기, 카드, 목록,
하단 고정 버튼), 다음 차이가 있다:

- 헤더 타이틀: "예정된 운동"
- 상단 카드: 썸네일(`MUSCLE_GROUP_IMAGES[workout.muscleGroup]`) + `name` + `date` /
  `level` / `duration` 메타
- 운동 목록: 각 아이템에 `exercise.name` + 세트×횟수×무게 표시
  - **보기 모드(기본):** 텍스트로만 표시 (`routines/[id].tsx`와 동일한 카드 스타일)
  - **수정 모드:** 세트/횟수/무게가 `TextInput`(`keyboardType="numeric"`, `set-entry.tsx`와
    동일한 input 스타일)으로 바뀜. 로컬 draft state로 편집하고, 화면을 벗어나거나
    "취소"를 누르면 draft 폐기
- 하단 버튼 2개:
  - **수정 모드가 아닐 때:** "수정" (보조 버튼) + "시작하기" (주 버튼, teal)
  - **수정 모드일 때:** "취소" + "저장" — 저장 시 draft 값을 검증
    (`Number.isFinite(n) && n > 0`, 실패하면 저장 막고 해당 필드에 inline 에러 표시)한 뒤
    `updateItem`을 아이템마다 호출하고 보기 모드로 복귀
- "시작하기" 핸들러:
  ```ts
  const handleStart = () => {
    markStarted(workout.id);
    router.push(`/workout/${workout.id}`);
  };
  ```
  `Date.now()`로 새 id를 만들지 않고 upcoming workout의 기존 id를 그대로 세션 id로
  쓴다 — 백엔드에서도 SCHEDULED→IN_PROGRESS가 같은 row를 PATCH하는 흐름이라 이 쪽이
  실제 동작과 맞다.
- `getUpcomingWorkout(id)`가 `undefined`를 반환하면(존재하지 않는 id) `routines/[id].tsx`와
  동일하게 `return null`로 처리한다 (새로운 에러 UI 패턴을 만들지 않고 기존 관례를 따름).

### `app/workout/[sessionId].tsx`

`buildLogsFromTemplate`을 호출하기 전에 `upcomingWorkoutsStore`에서 먼저 조회하도록
분기 추가:

```ts
function buildLogsForSession(sessionId: string, templateId: string | undefined): ExerciseLog[] {
  const upcoming = useUpcomingWorkoutsStore.getState().getUpcomingWorkout(sessionId);
  if (upcoming) {
    return upcoming.items.map((item) => ({
      id: item.id,
      name: getExerciseById(item.exerciseId)?.name ?? "알 수 없는 운동",
      targetSets: item.targetSets ?? 0,
      targetReps: item.targetReps ?? 0,
      targetWeight: item.targetWeight ?? 0,
      actualSets: "",
      actualReps: "",
      actualWeight: "",
      completed: false,
    }));
  }
  return buildLogsFromTemplate(templateId);
}
```

기존 `templateId` 기반 경로("내 루틴"에서 바로 시작하는 `routines/[id].tsx`의
`handleStart`)는 그대로 유지된다 — 그 흐름은 upcoming workout이 없는 즉석 시작이므로
계속 `Date.now()`로 새 세션 id를 만든다.

## 데이터 흐름 요약

1. 기록 탭 → 예정된 운동 카드 탭 → `/upcoming/{id}`
2. 미리보기 화면 마운트 → `getUpcomingWorkout(id)` 조회
3. (선택) "수정" → draft 편집 → "저장" → `updateItem` 반복 호출 → store 갱신,
   `templatesStore`는 무영향
4. "시작하기" → `markStarted(id)` (status → `IN_PROGRESS`) → `/workout/{id}`
5. 워크아웃 화면 마운트 → `sessionId`로 upcoming store 우선 조회 → 있으면 그 `items`
   (수정된 값 포함)로 로그 구성

## 에러 처리

- 존재하지 않는 upcoming workout id: `routines/[id].tsx`와 동일하게 `null` 렌더링
- 수정 입력값이 숫자가 아니거나 0 이하: 저장 차단 + 해당 필드에 inline 에러 텍스트
  (새로운 검증 패턴 — 기존 화면엔 참고할 만한 유사 처리가 없어 최소한으로 추가)

## 테스트 / 검증

프로젝트에 테스트 인프라(Jest 등)가 없어 기존 관례대로 iOS 시뮬레이터에서 수동 검증한다.

검증 시나리오:
1. 예정된 운동 탭 → 미리보기 화면으로 이동하고 워크아웃이 즉시 시작되지 않는지
   (홈 화면 "운동 중" 배너가 뜨지 않는지) 확인
2. "수정" → 값 변경 → "저장" → 미리보기 화면에 반영되고, "내 루틴"에서 같은 템플릿을
   열어봤을 때 원본 템플릿 값은 그대로인지 확인
3. 잘못된 값(빈 값/0/음수) 입력 시 저장이 막히고 에러 텍스트가 보이는지 확인
4. "시작하기" → 워크아웃 화면에 수정된 목표치가 반영되어 표시되는지, 세션 id가
   upcoming workout id와 동일한지 확인
5. `routines/[id].tsx`("내 루틴"에서 즉석 시작)는 기존과 동일하게 동작하는지
   (회귀 확인)
