# ADR-0001: Expo, Expo Router, TanStack Query, Zustand 기반 스택

- 상태: 채택됨
- 결정일: 2026-08-17
- 소급 작성일: 2026-11-24

## 맥락

프론트엔드 프로젝트를 새로 시작하는 시점이었습니다. iOS를 먼저 내고 백엔드(REST API)와 실제로 연동하며, 세트 타이머처럼 서버에 보내기 전까지 기기 안에서만 존재하는 상태가 있었습니다. React Native 경험이 거의 없는 1인 개발이라 시작 속도와 설정 부담이 중요했습니다.

## 결정

- 프레임워크는 **Expo**를 씁니다.
- 라우팅은 **Expo Router**(파일 기반)를 씁니다.
- 서버 상태는 **TanStack Query**, 기기 안에서만 있는 상태는 **Zustand**로 나눕니다.

## 검토한 대안

- **React Native CLI(bare)**: 시작 속도, OTA 업데이트, EAS Build를 쓰기 어려워 쓰지 않았습니다. 네이티브 설정이 꼭 필요하면 `expo prebuild`로 내려가기로 했습니다.
- 그 밖의 라우팅·상태 라이브러리를 비교한 기록은 없습니다.

## 결과

- 얻는 것: 빠른 시작, EAS Build와 OTA 업데이트, 화면 구조와 파일 구조의 일치. 서버 캐시와 화면 상태가 섞이지 않습니다.
- 감수하는 것: 이후 Live Activity 같은 네이티브 기능이 필요해져 Expo Go를 쓰지 못하고 개발 빌드를 씁니다. `ios/`, `android/`는 저장소에 두지 않고 빌드 때 `prebuild`로 만듭니다(CNG 방식).
