# ADR-0002: OTA 업데이트는 appVersion 런타임 버전 정책

- 상태: 채택됨
- 결정일: 2026-10-06
- 소급 작성일: 2026-11-24

## 맥락

JS만 바뀐 수정까지 매번 스토어 심사를 기다릴 수는 없어서 EAS Update(OTA)를 도입했습니다. OTA 번들은 같은 네이티브 코드를 가진 설치본에만 가야 합니다. 네이티브 코드가 다른 설치본이 새 JS를 받으면 앱이 깨질 수 있습니다.

## 결정

`app.json`의 `runtimeVersion`을 `appVersion` 정책으로 둡니다. 앱 버전(`version`)이 같은 설치본에만 OTA가 갑니다.

- JS와 에셋만 바뀌면 버전을 올리지 않고 OTA로 배포합니다(`npm run update:production`).
- 네이티브 의존성, 권한, 네이티브 설정, SDK가 바뀌면 버전을 올리고 새 빌드를 냅니다.
- 업데이트는 앱 실행 때 받아 다음 실행에 적용합니다.

## 검토한 대안

다른 런타임 버전 정책을 비교한 기록은 없습니다.

## 결과

- 얻는 것: 버전 번호만 보고 OTA 가능 여부를 판단할 수 있는 단순한 규칙.
- 감수하는 것: JS만 바뀌는 수정에서 버전을 올리면 기존 빌드가 그 업데이트를 받지 못합니다. 그래서 배포 전에 "네이티브가 바뀌었는가"를 사람이 확인해야 합니다. 이 판단이 틀리면 업데이트가 일부 설치본에 가지 않습니다.
